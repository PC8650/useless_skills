# CodeGraph 实测数据矩阵与版本复测清单

> **本文件包含**：`query` 匹配算法实测、体积实测完整矩阵（精度技巧 / `maxFiles` / bag 交互 / `node` 模式 / `files` 写法）、版本升级后高危复测清单。
>
> **本文件不包含**：参数与默认值（→ `params-quickref.md`）、陷阱的症状与正确做法（→ `pitfalls.md`）。
>
> **何时读本文件**：① 需要精确实测数字做判断；② 版本升级后按清单复测；③ 怀疑匹配算法或体积行为异常、需查完整矩阵。
>
> **何时不必读**：日常选参数（读 `params-quickref.md` 即可）、常规排障（读 `pitfalls.md` 即可）——两者的结论性数字已内联，无需来此查证。
>
> **权威性**：本文件是实测数据的**唯一权威源**；`params-quickref.md` 与 `pitfalls.md` 中的数字均为本文件的摘要，冲突时以本文件为准。
>
> 参数与默认值以本机实测为准（参照版本 1.6.x）；CodeGraph 迭代较快，**执行前建议用 `codegraph <command> --help` 核对当前版本的实际参数**。

## 1. `query` 匹配算法实测

### 1.1 匹配特性

| 特性 | 实测结果 |
| :--- | :--- |
| **子串匹配** | ✅ 支持（`binable` 命中 `XxxCaseVO` 类） |
| **大小写** | **不敏感**（`XXXCASEVO` 与 `XxxCaseVO` 结果相同） |
| **编辑距离** | ✅ 容差 **约 2~3**（非严格阈值，见 §1.2） |
| **前缀** | 非独立特性（由子串覆盖） |
| **完全无关词** | 返回 0（`ZZZZZZ`/`1234567890`） |

### 1.2 编辑距离非严格（MUST 注意）

同为 Levenshtein 距离 3，结果可能不同：

| 查询 | 距离 | 结果 |
| :--- | ---: | :--- |
| `XxxCaseVX`（3 处替换） | 3 | ✅ 命中 |
| `XxxCaseXXX`（3 处替换） | 3 | ❌ 不命中 |
| `XxxCaseXYZ`（3 替换+1 插入） | 4 | ❌ 不命中 |

**结论**：匹配算法**不是纯编辑距离**（可能为编辑距离 + 字符多重集/相似度混合），**MUST NOT** 依赖精确距离阈值预测命中。

**实用含义**：拼写错误（≤ 2 字符）基本能命中，**但也会引入噪声**——`query` 结果需人工核对，不能假定全部精确匹配。

## 2. 体积实测矩阵

### 2.1 `explore` 查询精度技巧（MUST 优先用文件名）

在 3,186 文件项目上，**用文件名（带扩展名）比用符号名精度高 3.5~8.3 倍**：

| 查询 | 符号名 | 文件名 | 降幅 |
| :--- | ---: | ---: | ---: |
| 符号名（如 `XxxVO`） | 12,478 B | **2,021 B** | 6.2× |
| 符号名（如 `XxxController`） | 15,896 B | **4,492 B** | 3.5× |
| 符号名（如 `XxxStatus`） | 20,203 B | **2,425 B** | 8.3× |

**原因**：符号名会匹配所有同名定义（含 getter/setter 等），文件名则直接锁定目标文件。**MUST** 在已知文件名时优先用 `Xxx.java` 作为 query。

### 2.2 `maxFiles` 生效条件

仅当结果文件数**超过** `maxFiles` 时才截断；未超时设多少都无变化（实测：精确查询默认仅 3 文件，`maxFiles 3/6/12` 输出完全相同）。

### 2.3 MCP `maxFiles` vs CLI `--max-files`

| 项 | MCP `maxFiles` | CLI `--max-files` |
| :--- | :--- | :--- |
| 工具声明默认 | 12 | 8 |
| **实测默认** | **8** | **8** |
| 硬上限 | 11（实测：设 12/15/20/30 均只返回 11） | 11（同） |
| 传 1 时 | 无 `source for N files` 尾部提示 | 同 |

**关键**：**MCP 工具声明的默认 12 与实际不符**——实测不传 `maxFiles` 时行为等同 `maxFiles: 8`（逐字节相同）。**MUST** 以实测值 8 为准。

**两者输出内容一致**：同查询同参数下，MCP 与 CLI 输出**仅末尾换行符不同**（CLI 多一个 `\n`），正文逐字节相同。

**文件选择顺序一致（实测）**：同查询同 `maxFiles` 下，MCP 与 CLI 的**入选文件列表及顺序完全一致**（已逐项对比 `maxFiles=2/3/5/8`，均逐项相同）。因此**可放心在 MCP 与 CLI 间切换**，不会因通道不同而得到不同文件集。

### 2.4 `maxFiles` × 多符号 bag 交互

- **bag 越大，默认输出越大**：bag 1 → 3 文件 / 12KB；bag 2 → 4 文件 / 17KB；bag 3 → 8 文件 / 24KB；bag 5 → 8 文件 / 25KB；
- **`maxFiles` 对 bag 同样生效**，但**输出体积非单调**（实测 bag 3）：

| maxFiles | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8+ |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 输出 | 10.4KB | 17.7KB | 20.9KB | 22.5KB | **26.8KB** | 25.4KB | 24.4KB | 24.1KB |

**原因**：`maxFiles` 改变的是**入选文件集合**（非简单截断），不同集合的源码长度不同，因此体积会波动。**MUST NOT** 假设"maxFiles 越小输出越小"。

**`maxFiles 1` 特殊**：输出不含 `source for N files` 尾部提示（实测），且体积最小（约 10KB）。

### 2.5 `explore` 多符号 bag 规则

- **去重**：重复符号完全去重（`A A A` 与 `A` 输出逐字节相同）；
- **顺序无关**：`A B` 与 `B A` 输出**仅标题行不同**，正文逐字节相同（已 diff 验证）；
- **大小写敏感**：`XxxVO`（12,478B）与 `xxxvo`（5,967B）结果不同，**MUST** 保持正确大小写；
- **多符号不叠加**：`A B` 输出（17,231B）**小于** `A`+`B` 之和（28,374B），因共享文件被合并去重。

### 2.6 `-f/--file` 用法要点

- 接受**文件路径或后缀**（如 `XxxVO.java`），用于在多个同名符号定义中**收窄到目标文件**；
- 无匹配时**不报错**，而是显示全部定义并附提示（`no match: show all with a note`）——因此**看到结果变多要警惕 `-f` 未命中**（见 `pitfalls.md` P4）；
- 对 `callers`/`callees`/`impact` 均可用，是**控制输出体积的第一手段**。

### 2.7 `node` 文件模式精读

当需要读取大文件（如 130 列宽表实体）的特定区段时，用 `--offset` + `--limit` 按行范围读取，**避免整文件载入**。`--symbols-only` 仅输出符号映射 + 依赖方，适合先看结构再决定读哪段。

**推荐流程**：`node --file <路径> --symbols-only` 先看结构 → 再 `node --file <路径> --offset N --limit M` 读目标区段。

**边界行为（实测）**：

- **`--offset` 越界**：不报错，返回提示 `has N lines — offset M is past the end`（实测 543B）；
- **`--offset 0` / `-1`**：等同从第 1 行开始（非报错）；
- **`--limit 0` / `-1`**：等同不限行数（返回全文）。

> 模式对比表与写法陷阱对照表见 `pitfalls.md` P10 / P11（含实测体积与错误写法）。

## 3. 版本升级后高危复测清单（MUST）

版本与参照版本主次版本不同时，按 `params-quickref.md` §5.2 执行重新校验，并**逐条复测**以下陷阱是否仍成立：

| # | 复测项 | 复测方法 |
| :--- | :--- | :--- |
| P1 | `--kind` 非法值是否仍静默返回空 | `query <已知符号> --kind bogus` |
| P2 | `-f` 短选项含义是否仍因命令而异 | 各命令 `--help` 对比 |
| P3 | `--limit` 是否仍为 per-definition | 对多定义符号设 `--limit 1` 看定义数 |
| P4 | `-f` 未命中是否仍显示全部定义 | `-f 不存在的文件.java` |
| P5 | `affected --filter` 短路是否仍成立 | `--filter "*.java"` 看是否返回输入文件本身 |
| P6 | `affected --depth` 默认值是否仍漏报 | 对比 `--depth 5` 与 `--depth 10` |
| P7 | `maxFiles` 体积是否仍非单调 | 对 bag 3 扫 `maxFiles 1..8` |
| P8 | `files` 默认输出规模 | 无参数 `files` 测体积 |
| P9 | `--format flat/grouped` 是否仍忽略 `--max-depth` | `--format flat --max-depth 1` 测体积 |
| P10 | `node` 符号模式是否仍忽略选项 | 加/不加 `--symbols-only` 对比输出 |
| P11 | `node --file` 写法是否仍要求路径作为值 | 两种写法对比 |
| P12 | `path` 参数形式是否仍不统一 | `status -p <path>` 是否报错 |

**兜底原则**：实测优先于文档；不静默套用；不假设向后兼容；参数不存在时改用 `--help` 列出的等价参数。
