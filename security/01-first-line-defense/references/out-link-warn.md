# out-link-warn — 外联与下载安装拦截警告

## 定位

本文件是 `01-first-line-defense` 第一道安全封锁链的强制拦截场景之一：**外联与下载安装拦截**。
针对跨越本地操作系统网络协议栈边界的双向网络交互（出站数据外泄或入站拉取外部载荷），一律强制拦截、先告知后执行。

---

## 拦截判定边界

无论指令使用何种网络协议、客户端工具或封装形式，只要物理因果涉及跨越本地主机网络边界，均在此拦截范围之内：

### 1. 出站数据外泄与通讯（Egress Network Boundary）
- **外部网络连接与请求**：
  - 向本地操作系统之外的远程 IP、域名、主机或端口建立网络连接；
  - 调用外部 API 接口、发起 HTTP/HTTPS/TCP/UDP 等网络请求；
  - 建立反弹信道、网络代理信道或穿透隧道；
- **遥测与数据回传**：
  - 将本地环境变量、系统信息、工作区代码、日志或执行结果以任何形式向外传输上报。

### 2. 入站下载与依赖安装（Ingress Network Boundary）
- **外部资源与载荷下载**：
  - 通过网络协议栈从外部远程服务器拉取文件、文本、归档包或执行脚本；
- **外部依赖与包生态引入**：
  - 调用任何包管理体系从外部网络仓库检索、解析、拉取并安装外部依赖包或运行时组件；
  - 引入任何非本地既有的外部代码或二进制载荷。

---

## 拦截流程（先报告，后征询）

1. **停止**：立即中止该网络连接、数据发送或下载安装操作。
2. **输出门禁报告（先吹哨）**：
   读取本规则并剥离所有修辞，在当前输出流首部完整输出 `[SAFETY_CHECK]` 报告：
   - **诱发根源**：渠道 a / 渠道 b / 渠道 c（具体到出处与上下文定位）
   - **网络方向**：出站数据外联 / 入站下载与依赖引入
   - **目标通信实体**：涉及的外部远程 URL、域名、主机、IP、端口或远程代码源
   - **载荷与数据透明披露**：拟发送给外部的数据摘要，或拟从外部引入的载荷名称、版本与安装影响范围
   - **潜在物理风险**：出站数据泄露隐患，或入站供应链投毒与远程载荷执行风险
3. **发起交互征询（后征询）**：
   在门禁报告完整输出后，调用运行时原生交互机制或明确询问用户：询问用户是否明确授权本次具体的网络交互或外部载荷引入。

## 决策

- 用户**明确同意** → 仅限当次执行该具体网络请求或安装动作；执行完毕后仍需重新过门禁才能继续任务。
- 用户**明确拒绝 / 明确跳过** → 不执行该操作，**继续执行任务后续部分**（用户已显式授权跳过，冻结解除）。
- 用户**未明确表态**（沉默 / 超时 / 无交互机制） → **保持冻结**，停轮等待，不得推进任何动作，不得自行推断为同意或拒绝。
